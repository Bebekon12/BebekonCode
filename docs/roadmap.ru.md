# Что ещё осталось сделать в BebekonCode

Состояние на 6 октября 2026 года, версия 0.3.0. Это работающая локальная основа приложения,
но ещё не полноценная среда с настоящими ИИ-агентами. Ниже план по приоритетам.

## Уже работает

- Приложение Windows в EXE, установщики EXE/MSI, русский интерфейс и логотип.
- Локальные проекты, независимые сессии, потоковый вывод, остановка и история SQLite.
- Файловый менеджер: просмотр папок, создание, чтение, редактирование и сохранение UTF-8,
  переименование/перемещение, подтверждённое удаление файлов и пустых папок.
- Проверка внешних изменений перед сохранением и защита несохранённого текста.
- Просмотр состояния Git и diff, открытие Проводника и отдельного окна PowerShell.
- Проверка стабильных выпусков GitHub, показ истории изменений, ручное скачивание.
- Поиск команд, сохранение положения окна и защита от второго экземпляра.

Локальное демо — симулятор. Оно не делает запросов к ИИ, не читает проект и не запускает
инструменты. Файловый менеджер — отдельные действия пользователя, доступные уже сейчас.

## 1. Настоящие провайдеры — главный следующий этап

- Подключить официальные адаптеры OpenAI / Codex и Anthropic / Claude Code.
- Реализовать официальный вход, несколько изолированных профилей аккаунтов, безопасное
  хранение учётных данных, обновление авторизации и восстановление сессий.
- Получать доступные модели от провайдера; правильно показывать ограничения, ошибки и квоты.
- Привязывать каждую сессию к выбранному аккаунту; не переключать аккаунты автоматически.

Перед реализацией нужно повторно сверить актуальную официальную документацию. Ранее выбранные
протоколы описаны в [плане провайдеров](providers.md), но ещё не проверены реальной интеграцией.

## 2. Управление процессами и действиями ИИ

- Ограничить дочерние процессы, вывод и время работы, корректно останавливать всё дерево
  процессов в Windows, обрабатывать сбои и восстанавливать состояние.
- Добавить интерактивные подтверждения для команд, изменений файлов, сети и операций Git.
- Сохранить защиту провайдера и проверять ограничения на уровне выполнения действий.
- Показывать предложение изменений, diff, выполнение, результат и журнал подтверждений.

Существующие профили разрешений — основа политики. Они пока не управляют настоящими
инструментами ИИ. Ручной редактор не является системной песочницей для недоверенных процессов.

## 3. Полноценная работа с проектом

- Встроенный терминал с интерактивным вводом, несколькими вкладками и управлением процессами.
- Изолированные Git worktree для параллельных задач, просмотр и применение изменений,
  коммиты и отправка только после явного действия пользователя.
- Редактор с подсветкой синтаксиса, поиском по проекту, вкладками, большими файлами,
  поддержкой других кодировок и наблюдением за внешними изменениями.
- Копирование, безопасное удаление в Корзину, расширенные операции с папками и проверка ACL.
- Управление проектами и сессиями: переименование, архивирование, удаление и экспорт истории.

## 4. Готовность к обычному распространению

- Подписать EXE/MSI, настроить подписанные автоматические обновления и восстановление после
  неудачного обновления. Сейчас обновления проверяются, но устанавливаются вручную.
- Проверить чистую установку, обновление старой версии и удаление на Windows 11.
- Проверить масштабирование, несколько мониторов, длительную работу, производительность,
  миграции, восстановление после сбоя и реальные сценарии обоих провайдеров.
- Завершить проверку безопасности учётных данных, запуска процессов и границ доступа.

## 5. После первой полноценной настольной версии

Делегирование между агентами, дополнительные официальные API (например, генерация изображений),
а затем защищённый мобильный клиент. Мобильный клиент, удалённый сервер и телеметрия сейчас
не реализуются: сначала нужны рабочие провайдеры и безопасное выполнение на компьютере.
