# 0.8.16 — паритет с Claude Desktop и расход лимита

## Почему расход был выше

Проверено по локальным журналам приложения (`workspace.db`) и транскриптам CLI в профиле
аккаунта, без новых модельных запросов:

- Кэш промпта между сообщениями работает: повторная запись кэша на всю историю возникала
  только после перерыва больше часа (как и в Desktop). Перезапуск CLI на каждое сообщение
  с `--resume` кэш не сбрасывает.
- Основной расход — повторное чтение большого контекста в каждом запросе. Приложение
  урезало набор инструментов Claude по сравнению с Desktop:
  - субагенты (`Agent`, в т. ч. Explore на меньшей модели) были запрещены — всё чтение
    файлов раздувало основной контекст Opus;
  - `ToolSearch` отсутствовал — схемы выбранных MCP загружались целиком в каждый запрос
    (Unity MCP: около 33 тыс. токенов на запрос; старт чата 57 тыс. против 25 тыс. без MCP);
  - `TodoWrite`/`Task*`, `WebSearch`/`WebFetch`, `Monitor` были запрещены;
  - ложные отказы хука (`.env` внутри `process.env`, `System.Environment`, `os.environ`;
    команды длиннее 4000 символов; слова вроде `password=`) заставляли модель повторять
    попытки другими способами.
- Список навыков передавался как JSON с полными путями (около 1,5 тыс. токенов) плюс
  отдельная папка `--add-dir` на каждый навык; порядок папок зависел от `HashMap`.

Точный множитель относительно Desktop не измерялся: для честного сравнения нужен одинаковый
запрос в обоих клиентах. Устранены конкретные источники лишних токенов.

## Изменения

- `--tools` для режимов с записью: штатные `Read, Glob, Grep, Edit, Write, Bash, PowerShell,
TodoWrite, Task*, ToolSearch, Agent, Monitor, WebSearch, WebFetch`. В чтении/Plan добавлены
  только списки задач. `Agent` разрешён лишь в обычном чате; команда и автокоманда остаются
  без вложенных агентов. Вызовы инструментов субагентов проходят тот же хук.
- Навыки: одна общая папка `--add-dir` и строка с именами; порядок детерминирован.
- Хук: проверка учётных данных по границам слов; в автоматических режимах нет отказов по
  длине и по маскированию; в ручном режиме длинная команда показывается в карточке, а не
  отклоняется. Папка памяти `<профиль>/projects/<проект>/memory` доступна на чтение и
  запись (в режиме чтения — только чтение). Текст отказа для модели теперь точный.
- Нет лимита 1 час на ход и 4 минут на подтверждение: ход ждёт ответа или «Стоп».
- События `tool_started`/`tool_finished`/`todo_update` с короткой маскированной сводкой
  (путь, шаблон, первая строка команды или её описание, счётчики строк). Содержимое файлов и
  вывод инструментов не сохраняются. Codex передаёт команды, MCP, веб-поиск и правки файлов
  в том же формате (счётчики строк — из diff Codex).
- Интерфейс: чередование текста и свёрнутых групп действий, карточка целей, строка текущего
  действия со временем, пузырь сообщения пользователя, растущее поле ввода, параметры под
  полем. Сокращены описания.

## Ограничения

- `AskUserQuestion` (карточки вопросов Desktop) и встроенный `Skill` недоступны.
- Shell и MCP Claude в Windows по-прежнему без песочницы ОС.
- Официальная документация не перезапрашивалась в этой сессии: имена инструментов и
  терпимость `--tools` к неизвестным именам проверены на установленном Claude Code 2.1.294
  (строки бинарника и `initialize` control request без модельного запроса).
- Реальные модельные запросы для сравнения расхода не выполнялись.
