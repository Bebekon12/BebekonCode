# Команда Claude и Codex: исправления 0.8.11

## Что произошло в приведённом примере

Журнал показывает отдельный запуск планировщика, шесть запросов его основного цикла и отсутствие
ожидаемого структурированного результата. Установить по этому фрагменту точную причину отсутствия
поля нельзя. Гипотезы о фильтрах инструментов или конкретном ответе модели не выдаются за доказанный
диагноз. Исправление устраняет зависимость командного запуска от платного JSON-планировщика.
Unity-задание использовалось как пример входа, файлы игры не менялись.

## Текущая схема

Один ведущий изменяет проект и проверяет результат. До двух специалистов только читают и дают
разные рекомендации. По умолчанию в смешанной команде Codex ведёт реализацию, Claude отвечает за
архитектуру, механику, UX и визуальные требования; ведущего можно сменить. Это распределение
ответственности, а не утверждение превосходства одной модели.

В ручной команде сохраняются различные пользовательские роли; пустые/одинаковые роли получают
разные области. Автокоманда назначает области локально, без запроса к модели. Для примера Unity
выделяются механика/управление/визуальные требования и риски/критерии приёмки. Специалисты не
редактируют файлы и не вызывают внешние MCP, вложенных агентов или компьютерные инструменты.
Инструменты, необходимые для реализации, использует ведущий с разрешениями выбранного чата.

Повторные ходы используют сохранённые сессии специалистов. Новая роль, модель или привязка
аккаунта получает отдельную сессию. Начальный общий контекст ограничен 8 КБ; передаваемый ответ
ведущего и вклад каждого специалиста — примерно 6 КБ с явной отметкой сокращения. История не
дублирует текущую задачу. Точные короткие продолжения вроде «Продолжай» обращаются только к ведущему.

## Расход и качество

- Ведущий и два специалиста: 5 запусков адаптера в прежней команде → 3.
- Автокоманда с одним выбранным агентом: прежние 3–6 запусков → 1.
- В нативном тесте с двумя агентами: подробная задача → 2 запуска; «Продолжай» → 1.

Запуск адаптера может включать несколько модельных обращений. Эти числа не являются процентами
экономии токенов или лимита. Кэш, длина задачи, инструменты и качество модели влияют на реальный
расход; живые сравнения запрещены пользователем. Обещаний «идеального» результата нет.

## Codex и диагностика

Проверены thread/resume и thread/fork, привязка аккаунта, отмена до turn/start, отсутствие новых
ходов при fork, режим Fast, отдельный прогресс, защита от повторных завершений и чужих счётчиков.
При неизвестной исходной сумме токены отмечаются неполными. Командные потоки отключают native
agents и модельный reviewer разрешений. Отчёт запуска содержит только технические метаданные,
без текста запросов/ответов и секретов. Диагностика не суммируется с usage повторно.

Использованы только fake CLI/RPC, mock-провайдер и публичные операции без inference.
