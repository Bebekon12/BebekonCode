# Контекст, сообщения во время работы и наглядные ответы — 0.8.12

## Что обнаружено

В 0.8.11 статистика показывала расход запуска, но отдельного индикатора активного контекста не было.
Редактор, вставка изображений и выбор файлов блокировались при работающем агенте. Очередь существовала
в отдельном окне и принимала только текст. Markdown-картинки заменялись заглушкой, а ссылки можно
было только копировать. Командный ответ уже поддерживал простые графики и карточки; обычным чатам
не хватало явного предпочтения подачи и отображения изображений.

## Реализованное управление контекстом

Внизу чата доступен пункт **«Контекст»**. Он показывает последнее измерение, размер окна и процент
только при наличии данных. Для Codex берётся `last.totalTokens`, а не накопительная сумма всех ходов;
для Claude — вход последнего сообщения с cache read/write. Ёмкость Claude берётся только из
однозначно сообщённого `modelUsage.contextWindow`. После сжатия старое заполнение сбрасывается в
«не сообщено» до нового измерения. Смена модели/аккаунта не переносит прежний показатель.

Регулируется **ориентир сжатия**, а не аппаратная ёмкость модели. Codex получает
`model_auto_compact_token_limit`. Claude получает `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (100K–1M,
ограничивается окном модели) и по выбору `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`; более высокий процент
не отменяет штатное раннее сжатие. По умолчанию используются настройки провайдера. Настройки
сохраняются для чата, меняются между ходами и учитываются при проверке конфигурации очереди.

Кнопка **«Сжать контекст сейчас»** доступна после появления нативной сессии. После пояснения о расходе
и потере деталей отправляется штатная операция. Видимая история и файлы сохраняются. Claude получает
именно встроенную `/compact`, без инструментов и пользовательских источников настроек; Codex —
`thread/compact/start`, без обычного запроса на выполнение задачи. Команда не запускает специалистов.

Источники: [настройки Codex](https://learn.chatgpt.com/docs/config-file/config-reference),
[переменные Claude](https://code.claude.com/docs/en/env-vars),
[формула контекста Claude](https://code.claude.com/docs/en/statusline),
[встроенная команда compact](https://code.claude.com/docs/en/agent-sdk/slash-commands).

## Уточнение или очередь

Редактор и вложения доступны во время ответа. Выбор над редактором:

- **«Уточнить текущую задачу»**: для ведущего Codex или Claude. Для Codex вход поступает в тот же активный ход; прикреплённые
  изображения передаются как `localImage`, другие файлы — как проверенные локальные вложения.
  Успех показывается после подтверждения провайдера. При смене/завершении хода сообщение остаётся
  в редакторе; автоматического повтора нет. Во время работы специалистов ведущий может ещё не быть
  готов принимать уточнения — тогда можно выбрать очередь.
- **«После текущей задачи»**: для обоих провайдеров. Карточки находятся над редактором; текст можно
  менять, задания переставлять, отменять и продолжать после паузы. Вложения сохраняются на диск,
  а перед отправкой сверяются путь и SHA-256. При изменении файла задача завершается ошибкой вместо
  отправки других данных. Перезапуск приложения не запускает очередь без подтверждения.

Для Claude дополнение отправляется в уже работающий CLI через официальный stream-json. UUID и
штатный replay подтверждают получение. По [документации Claude Code](https://code.claude.com/docs/en/interactive-mode#queue-messages-while-claude-works)
движок может подхватить сообщение после инструментов в том же ходе или обработать следующим нативным
ходом. Подсказка об этом видна в редакторе. Приложение не прерывает ответ и не перезапускает CLI.

Первый итог закрывает приём новых дополнений; уже отправленные сообщения обрабатываются до выхода
CLI. Повторные подтверждения/итоги не дублируют вывод. Если CLI выдал несколько результатов внутри
одного запуска, их расходы учитываются отдельно и суммируются в диагностике запуска. Ошибка или
неподтверждённое получение не запускают автоматическую повторную отправку. Очередь приложения
остаётся отдельным вариантом, гарантированно после текущей задачи.

## Подача ответов

Пункт **«Контекст → Оформление ответа»** предлагает стандартный, краткий, подробный и наглядный стиль.
Последний просит у выбранной модели структурированный ответ и полезные реальные иллюстрации/графики.
Отдельного запроса к модели для оформления нет. Стандартный режим не добавляет стилевую инструкцию.

Изображение из Markdown отображается рядом со следующим текстом на широком экране, на узком — над
текстом. Доступны подпись, источник и увеличение. Публичные HTTPS-ссылки открываются по нажатию.
Изображения загружаются лениво, без cookies при cross-origin запросе и без referrer. Недоступный
адрес/CORS даёт понятную заглушку и ссылку на источник. Локальные и командные URL не исполняются.

Добавлены линейные графики из ограниченного JSON: подписи осей, значения при наведении и таблица
исходных данных. Существующие столбцы, метрики, палитры, приоритеты, таблицы и копирование кода
сохранены. HTML/скрипты ответа не выполняются. Ссылка в ответе не означает, что приложение проверило
достоверность источника; стиль не гарантирует качество фактов и не даёт модели новые инструменты.

Это реализация визуальных приёмов в нашем приложении, а не копия закрытого браузерного ChatGPT.
[Официальные визуализации](https://learn.chatgpt.com/docs/visualizations) подтверждают роль наглядного
представления данных; здесь используется ограниченный локальный формат вместо произвольного HTML.

## Проверки и установка

Проверяются только fixtures, mock и публичные операции без inference. Реальные модельные ответы,
экономия токенов, живое сжатие и steering авторизованного аккаунта не выполняются по условию пользователя.
Подтверждено:

- `cargo fmt --all -- --check`, `cargo check --workspace -j1`, `cargo clippy --workspace -j1 -- -D warnings` — успешно.
- Rust: 133 теста пройдены, 5 проверок среды провайдеров явно пропущены. Включены активный `turn/steer` с изображением и ошибкой завершившегося хода, нативные маршруты сжатия обоих провайдеров, настройки/привязка аккаунта, контекст без суммирования расхода, проверка изменённых вложений очереди.
- `npm run typecheck`, 50 frontend-тестов, `npm run build` — успешно. Vite сообщает только рекомендации по размеру основного chunk и смешанному static/dynamic импорту Tauri API.
- 34 Playwright-сценария пройдены в совокупности полного запуска и адресных повторов; новые проверяют настройки, редактирование во время ответа, очередь с вложением, живое уточнение в одном ходе и визуальный ответ в обеих темах.
- Проверка официального Codex 0.160.1 в пустом отдельном профиле: `initialize`/`thread/start` с числовым порогом приняты, null отвергнут. `turn/start` не вызывался. Пустой поток без rollout не позволяет проверить resume; этот пробный ответ не выдаётся за проверку живой истории.
- SDK Claude 0.3.295 содержит публичное поле `ModelUsage.contextWindow`; секреты и транскрипты официальных клиентов не читались.

Демонстрационное оформление проверено по [светлой](../test-results/conversation-rich-light.png) и
[тёмной](../test-results/conversation-rich-dark.png) версиям. Это искусственные данные теста, не ответ GPT-6.

Нативные `scripts/native-workflows.mjs` и `scripts/native-smoke.mjs` пройдены на конечном release-файле
и повторно на установленном приложении в отдельных тестовых профилях. Проверены реальный Tauri IPC,
SQLite, сохранение стиля, отправка вложения из очереди, история, файлы, Git diff, worktree, контрольные
точки и команды. Отдельный fixture проверяет живой ввод Claude с максимальными 6 МиБ изображений,
повторный replay, два результата одного CLI и отсутствие зависания при закрытии stdout.
