# Работа без повторных подтверждений — 0.8.15

По запросу владельца от 15 октября 2026 года убраны добавленные приложением повторные
подтверждения для сочетания «Полный доступ» у одного участника и «Авто в проекте» у другого.
Профили применяются отдельно к каждому участнику обычной команды и автокоманды.

- Codex «Авто в проекте»: штатный `approvalPolicy=never` при запуске/продолжении потока
  и запуске хода, с сохранением `workspace-write`. Разрешённые команды выполняются;
  запрос расширить доступ отклоняется сразу, без карточки ожидания.
- Claude «Авто в проекте»: штатный `dontAsk` с `permissions.allow` для Edit, Write,
  Bash, PowerShell и выбранных MCP. Файловые инструменты проходят проверку границ проекта.
  Shell и MCP на Windows не изолированы песочницей ОС; этот режим не обещает ограничить
  произвольный shell-скрипт каталогом проекта. Дополнительного модельного классификатора нет.
- Claude «Полный доступ»: штатный `bypassPermissions`; удалены принудительный `mcp__*`
  в списке ask и ручная остановка каждого MCP-вызова в хуке приложения. В `Auto · Claude`
  также убрана эта добавочная остановка, решения продолжает принимать классификатор Claude.
- Провайдерские запреты не разрешаются автоматически: неожиданный запрос разрешения в
  `workspace_auto`/`full_access` отклоняется. Поэтому инструмент с обязательным участием
  человека может оказаться недоступен, но приложение не будет ждать на карточке согласия.
- Ручной режим и «Только чтение» сохраняют своё поведение. Встроенный раздел «Компьютер»
  использует отдельный мост с собственным подтверждением действий; он не является выбранным
  внешним MCP-сервером. Ограничение full_access для автоматических работников не изменялось.

Проверки исходников: cargo fmt/check/test/clippy (`-D warnings`), TypeScript и frontend build

Браузерные сценарии: 8 пройдено (Claude, обычная команда/автокоманда, доступ и инструменты).
Фиктивный CLI и RPC проверяют отсутствие ApprovalRequested, повторные MCP-вызовы, переход
Codex к never при продолжении сессии, сохранение песочницы, отклонение неизвестных MCP и
запретных путей, работоспособность ручного режима. Реальные Claude/Codex-запросы не выполнялись.
Справка реально установленных CLI (`--help`, без обращения к модели) отдельно подтвердила
поддержку `dontAsk` у Claude и `never`/`workspace-write` у Codex.
